# 체육 교실 · PE Class

초등 체육 수업용 정적 웹앱입니다. 배드민턴, 플라잉디스크 얼티밋, 피구, 팀편성, 대진편성을 왼쪽 메뉴에서 선택합니다. 기리공작소 버전은 v2.0.6입니다.

- 배드민턴은 기존 규칙 시범과 유튜브 실사 영상을 사용합니다.
- 얼티밋은 수업용 PPT를 바탕으로 경기장, 패스와 이동, 득점, 공격권 교체, 파울과 수비, 풀을 다룹니다. 기술 시범에는 백핸드, 포핸드, 양손 받기 영상이 있습니다.
- 얼티밋의 공식 판정은 [WFDF Rules of Ultimate](https://rules.wfdf.sport/)를 참고했습니다. 던지기 영상은 [조지아대학교 공개 교재](https://open.online.uga.edu/ultimate/chapter/skillsandtechnique/), 받기 영상은 [Manhattanville University 자료 목록](https://mville.libguides.com/c.php?g=370062&p=2500503)에서 확인할 수 있습니다.

## 팀편성과 대진편성

왼쪽 하단 팀편성에서 직접 입력 또는 PC용 XLSX 양식으로 명단을 등록합니다. 특성 미입력은 중으로 처리합니다. 반별·남녀 분리·신장별은 분리 조건이며, 나머지는 팀별 균형 조건입니다. 분리 조건이 충돌하면 조건이나 팀 수를 바꾸도록 안내합니다. 분리 조건을 지키는 범위에서 팀별 인원 차이를 최소화합니다.

편성 기준은 팀 수와 팀당 인원수 중 하나를 선택합니다. 팀당 인원수는 상한으로 사용하며, 필요한 팀을 만든 뒤 인원 차이를 줄입니다. 혼성은 성별 인원과 분리 조건이 허용하는 한 최대한 많은 팀에 두 성별을 배정합니다.

학생 이름 옆의 ‘제외’로 해당 학생을 팀편성에서 빼고, ‘다시 포함’으로 되돌릴 수 있습니다. 인원이 적은 팀이 생기면 그대로 두거나 같은 분리 조건을 충족하는 다른 팀의 학생을 자동 또는 수동으로 중복 배정할 수 있습니다.

학생 명단과 특성, 가져온 참가 팀, 대진표와 승패 기록은 같은 사이트의 같은 브라우저에 보관합니다. 대진표 초기화는 대진표와 승패 기록을 지우고 참가 팀은 유지합니다. 참가 팀 초기화는 대진편성으로 가져온 참가 팀과 해당 대진 기록을 지우며, 팀편성 결과는 다시 가져올 수 있습니다. 팀편성에서 명단을 삭제하면 저장된 명단과 특성, 대진편성 자료도 삭제됩니다.

대진편성에서 팀을 가져오면 팀 번호가 그대로 이어집니다. 토너먼트는 단판 탈락 또는 패자조를 포함한 순위 결정전으로 만들 수 있습니다. 승리 팀을 선택하면 다음 대진이 채워집니다. 리그는 풀리그, 부분 리그, 조별 리그, 스플릿 리그를 제공합니다. 라운드마다 승리 팀을 선택하면 팀별 승·패와 승률을 갱신합니다. 부분 리그에는 같은 반 팀끼리만 진행하는 옵션이 있습니다. 스플릿 리그에서는 반별·성별로 1차 풀리그와 2차 상·하위조를 나눌 수 있습니다. 혼성팀이 포함되면 성별 진행을 선택할 수 없습니다. 1차 성적을 반영하려면 상·하위조를 수동으로 배정합니다.

‘이미지 저장’에서 PNG 또는 JPG, 한 장 또는 여러 장을 선택합니다. 이미지는 흰 배경으로 생성되며, PC Chrome 또는 Edge에서 저장 위치를 지정합니다. 내보낸 팀편성 이미지에는 학생 이름이 들어 있습니다. 앱에서 명단을 삭제해도 별도로 저장한 이미지 파일은 삭제되지 않습니다.

대진표의 ‘동시 진행 경기 수’에는 사용할 수 있는 경기장 수를 입력할 수 있습니다. 비워 두면 동시 경기 수 상한 없이 배치합니다. 중복 참가 학생이 들어간 팀들의 경기는 서로 다른 라운드에 배치하며, 가능한 경우 사이에 다른 경기를 넣습니다. 두 팀이 서로 맞붙으면 중복 학생이 한 팀으로만 출전하도록 안내합니다.

팀편성 문서는 외부 스크립트를 로드하지 않으며 CSP로 네트워크 연결을 차단합니다. 엑셀은 브라우저에서만 해석하고 서버에 업로드하지 않습니다. 저장 명단과 결과에는 특성 값을 표시하지 않습니다. 편집 및 엑셀 불러오기는 특성 노출 안내창으로 보호하며, 페이지를 나가면 편집 화면을 제거합니다. 공용 기기에서는 사용을 마친 뒤 명단을 삭제하세요.

## GitHub Pages에 반영

1. ZIP을 풀고 `pe-class` 저장소의 `main` 브랜치 루트에 **압축 안의 파일**을 올려 한 커밋으로 저장합니다. `index.html`과 `.nojekyll`이 저장소의 가장 위에 있어야 합니다.
2. Settings → Pages에서 Deploy from a branch, `main`, `/ (root)`를 선택합니다.
3. Actions에서 배포 성공을 확인한 뒤 Pages 주소를 엽니다. 같은 저장소를 업데이트할 때는 수정된 파일을 커밋하면 됩니다.

공유한 버전을 표시하려면 배포 커밋에 `v2.0.6` 태그를 붙이거나 해당 태그로 GitHub Release를 만듭니다. 로컬 미리보기와 GitHub Pages는 주소가 달라 브라우저에 저장된 학생 명단과 대진 기록을 각각 관리합니다.
